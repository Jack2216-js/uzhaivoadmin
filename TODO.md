## Overview and worker proof moderation
- [ ] The Overview welcomes Boss at 9025421145 and shows eight parallel exact-count Supabase statistics: jobs, pending worker proofs (submitted proof count or pending-application fallback), pending owner verifications, workers, owners, verified owners, approved jobs, and applications. It lists up to five newest submitted worker proof submissions with job title and up to five pending owner verifications; refreshes every 10 seconds. The live schema has no `owner_verifications`, the `users` table lacks badge fields, and `jobs.status` is absent; the app temporarily reports active jobs from `jobs.is_active` instead.
- [ ] Worker Proofs loads submitted `proof_submissions` without the unsupported `jobs` foreign-key join and displays its `job_title`; it falls back to pending `job_applications` using their confirmed `jobs` relationship. Search, Aadhaar/license filter, refresh, loading skeleton, realtime INSERT subscription, worker call links, proof images and image zoom/download/action modal are implemented. Submitted proofs have no joined owner/contact detail until the job-to-owner mapping is confirmed.
- [ ] Approving a proof updates `proof_submissions.status` to `approved`, and updates one matching `job_applications` row to `approved` with `updated_at` when a match exists; if no application exists, only the proof is changed. Rejecting asks for a reason and updates the proof/application status, but the reason cannot be persisted with the current schema. `jobs` has no `status` field, so job approval is not written; application fallback records are moderated through `job_applications`.

- [ ] The queue loads pending owner verifications newest-first, supports owner phone/name search, Aadhaar/Voter ID/License document filters, refresh, realtime INSERT subscription, loading and empty states, owner call link and `verified_by` label. These backend behaviors await a mapped relation and secure auth/RLS.
- [ ] Each verification displays both document types and all four front/back images, has click-to-zoom, four-photo modal, download links, approve/reject controls, and an explicit private-data warning. The app must not fetch or display private documents from an unprotected anon endpoint.
- [ ] Approve updates the owner verification status, timestamp, and `verified_by=9025421145`, then sets the owner profile `is_verified_owner`, `blue_tick`, and `verified` to true. Reject asks for a reason and stores `rejection_reason`. Never fetch `gov_id_url` in general worker/owner list queries. A protected schema and a real authenticated admin session are required before enabling these actions.
